# v2.0.0 发布说明

日期：2026-11-07。本包包含最新 `/map` 素材和代码审查后的修复，版本号继续保持 **v2.0.0**。同版本旧包与本包内容不同，请使用 `dist/manifest.json` 的 SHA-256 核对。

## 修复范围

1. **旧队列迁移**：兼容已核对的远端 main `cdcd162`、codex `920cf48` 的 `pending` / `queued_at`，以及本地 `pending_posts` / `pending_news`。转换前备份状态，Companion 先复制截图再提交新状态，保留各群尚未成功的目标；迁移失败、未知版本或损坏状态会暂停该推送通道，保留原文件。
2. **新闻去重**：采用与已核对 codex 兼容的 `v2:` 稳定内容指纹，排除独立相对时间标签。原 SHA1 基线在首次捕获时静默转换；已有待补发队列仍独立重试。该次基线转换不主动补发刚捕获的文章，以免把同一新闻当作新内容。
3. **主目录保护**：校验目录与别名字段，在候选对象上完成建索引后，整体保存为 `primary_snapshot.json`。坏响应、别名失败、索引失败不会覆盖上一个有效快照；旧 `catalog.json` / `aliases.json` 可继续读取。
4. **翻译缓存持久化**：串行完成序列化与原子替换，防止旧写入覆盖新结果。取消与卸载等待已启动写入；磁盘失败保留脏状态供后续重试。
5. **API 请求头隔离**：共享会话默认只含公开头；仅在协议、主机、端口都匹配社区 API 时加联系信息，每次重定向重新检查。跨源携带 JSON 请求体的重定向被拒绝，重定向链共用总超时预算。
6. **本地卡片路由**：`companion_backend=local` 时 `/dss` 和 `/planet` 直接调用 Pillow 服务。
7. **关联集合更新**：护甲与被动表按同批候选校验，整体保存为 `dionatha_armor_snapshot.json`，允许同步改名/改引用；中断后重启读取一致的快照。其他集合仍可独立刷新。
8. **原样译文处理**：合法响应中译文与输入相同，不再触发全局 60 秒瞬态故障窗口。
9. **候选唯一查询**：名称加类别仍有歧义时，卡片提供来源/集合限定查询 ID，例如 `dionatha:stratagems:sta-x3-wasp-launcher`。
10. **失败保留与退避**：增加排队时间、各群重试状态、条数/时长/截图总字节限制；清理注明原因，磁盘状态提交失败时不提前确认新内容已入队。

这是以远端 main `cdcd162` 为基础整合本地 v1.10.5 开发线和审查修复的版本，不是完整合并远端 codex。Jerry 地图、静态中文 Wiki 等分支独有功能不在本包中。

## 默认推送策略

| 配置 | 默认值 | 说明 |
|---|---|---|
| `push_pending_max_entries` | 100 | 每个来源最多 100 条待补发，超出清理最早记录 |
| `push_pending_retention_days` | 7 | 最多保留 7 天，超期不再补发 |
| `push_pending_image_max_mb` | 128 | Companion 活动待补发截图总容量为 128 MiB |
| `push_retry_base_seconds` | 60 | 首次失败下轮重试；再次失败指数退避，最多 1 小时 |

达到边界意味着放弃被清理记录的后续补发，日志会说明原因。单张超过总截图预算的新闻会记录警告并跳过。遗留无时间记录会使用截图修改时间或迁移时间作为起点。退群清理仍要求 OneBot 最新群列表与在线状态有效；上传失败本身不会被当作退群。

## 安装、迁移与回滚

1. 备份当前插件代码及实际插件数据目录，停止插件后覆盖安装本次 `dist/astrbot_plugin_Helldivers-v2.0.0.zip`，或内容相同的通用文件名 ZIP，再重载。
2. 识别到旧格式时，每个推送目录自动保存 `state.before-v3.<摘要>.json`，新状态使用 `state_version: 3`。Companion 保留旧 `pending_*.png` 供回滚；活动图片位于 `outbox/`。备份与旧图片不计入活动截图容量，需要在确认升级后自行归档。
3. 迁移后记录仍受期限/容量策略约束。已核对格式可以迁移，不代表任意服务器私改格式都受支持；未知/损坏状态不会静默当空队列覆盖。`/hd2订阅列表` 和 `/hd2ping` 会报告状态保护，修复缺失图片或恢复备份后再重载。
4. 原版本已忽略并覆盖的队列，无法从空状态自动重建，须恢复覆盖前的备份。首次稳定指纹基线转换也不会恢复过去未保存的文章。
5. 回滚应停止插件后恢复旧代码与对应旧状态/截图；不要让旧代码直接读取 v3 状态。旧 v2.0.0 ZIP 自动归档在 `dist/archive/`，构建不会清空其他历史包。

源码同步到 GitHub `main`，保留此前提交历史。本次未部署到服务器，未创建 GitHub Release，也未发送 QQ 消息。

同步时保留了远端 main 的预热目标自动补全、浏览器就绪检查、结束任务重启、失败截图下的队列重试及目录别名补全/退避；相应旧回归场景已适配 v3 队列。依赖下限继续采用远端的 aiohttp>=3.10.0。
